## 方法与隔离

运行项目为 `oj-acceptance-22950a43dd`，单次完整运行约 6 分 36 秒。
测试自行生成数据库、密码、回环端口和 Mailpit；不读取开发 `.env`，
不向 QQ 发邮件，也不使用真实旧库。20 名学生通过真实 HTTP 并发提交；
浏览器覆盖的是独立学生、教练、管理员会话，并非 20 个持续运行的完整浏览器。

榜单计算器只使用预先给定的正确结果及服务端提交时间，
不读取服务端实际 verdict / score 来推导预期榜单。
固定例子的 3 项计算器单元检查通过，并加入 GitHub CI。
本轮构建还通过了 14 项 JUnit、前端构建与格式检查。
完整 Docker / 浏览器验收通过本地命令运行，未冒充 GitHub CI 的执行结果。

实际杀死测试 worker 后，只在独立测试库注入过期 `lease_until`，
再由真实扫描器、队列和 worker 重试；没有等待生产默认的 240 秒租约。
内存错误使用独立 5000ms / 64MiB 题目，避免时间和内存边界同时竞争。

旧版使用原 Django 镜像内 APIClient，新版通过单独导入库的 Java API 发出真实 HTTP。
比较对象是明确列出的业务字段，不是两个完整线上系统的所有响应字节。
预期差异包括 Token / JWT、字段及日期表示、中断评测重新排队，
以及旧版常规接口不返回源码而新版允许作者查看；源码另与导出快照核对。

API、judge、web 镜像按 image ID 固定。应用基线为 `b5d51ee`，
加上本次判题资源归属标签修改；原运行中的 OJ 容器未被重建。
镜像 ID、工作区差异摘要、每次预期/实际结果和阶段耗时保存在
[脱敏原始报告](machine-acceptance.json)。浏览器 trace、配置、快照与原始日志仅保留在忽略目录。
